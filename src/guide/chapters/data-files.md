# Data files and downloads

Some observations are too big for a table cell: an NIR spectrum is hundreds of readings for one sample. Such a variable
is on a complex scale, and each record cites a data file instead of holding a value. Block 1's spectra are recorded
already; this chapter records those of block 2's grain samples, each as a file, and fetches one back.

> [!WHO]
> To submit: those who can read the study, with Write access to a team. To download: whoever can read the file, once
> they accept the licences of the studies whose data cites it. Here, Lena Lab, of the Grain Quality Lab.

## Before you start

The study needs to exist, and a variable on a complex scale: here, Grain Quality 2025, and NIR spectrum. Submitting data
is shown in [Recording observations](/guide/recording).

![Data files and downloads](data-files.mp4)

## Steps

1. **Submit data, for the samples the files describe.** In Grain Quality 2025, Lena chooses the laboratory, the grain
   samples of block 2 that arrived there, and the variable NIR spectrum. {#choose}
2. **Each cell cites files: 📎 Manage uploads them.** The column takes the day the spectra were read. A sample's CSV is
   uploaded as a data file, with a description and its format, and chosen for its cell; the others are uploaded the
   same way. {#files}
3. **Submit makes the dataset.** Each record cites its sample's file, and the file is kept in BreedGraph's file store.
   {#submit}
4. **In curation, a record's files can be downloaded.** Get Link asks for the file, once the study's licence is
   accepted, and Download fetches it. {#download}

## Who sees what

> [!SEES]
> A data file has a control team and release of its own, chosen as it is uploaded: those who can read it can download
> it, after accepting the licences of the studies whose data cites it, as loading that data asks.

> [!NOTE]
> A file that has not been used for a while may be moved to the archive. Get Link then asks for it back, showing its
> progress, and Download is offered once it is back. The demonstration site has no archive, so its files are always
> at hand.
